# Product requirements: JellyScore

## Goal

Automatically find a likely theme song on YouTube for each eligible movie or TV series in Jellyfin, save it where Jellyfin recognizes it, and let an administrator view, replace, or remove plugin-managed downloads. False matches and overwriting a user's files are worse than leaving an item without a theme.

## Scope and users

- **User:** a Jellyfin server administrator with writable movie/TV library folders.
- **Supported items:** physical `Movie` and `Series` items in selected libraries. One theme per physical movie/series folder. Episodes, seasons, virtual items, extras, and unsupported/read-only folder layouts are out of scope.
- **Discovery:** new eligible items after plugin installation and a manually started whole-library rescan. Installing the plugin must not silently download themes for the existing library.
- **Control surface:** an administrator-only plugin dashboard page, with settings, scan progress, and a list of plugin-managed downloads.

## User experience

1. Automatic processing of newly added items is enabled by default. The admin selects libraries and can start a full rescan; nothing is processed until a library is selected.
2. On a new movie or series, the plugin waits until its title/year and physical folder are available, checks for existing theme songs, searches YouTube, rejects ineligible results, and downloads only a well-supported match. Otherwise it leaves the item unthemed and records “No match found”; no admin action is requested.
3. The page lists managed downloads with Jellyfin item name/type/year/library, the selected YouTube title and link, match score and evidence, file location, date, and status. Rows have **Refresh** and **Delete** actions.
4. **Refresh:** exclude the currently selected YouTube video for this item permanently, search/re-rank, and try the next highest-scoring eligible *different recording*. Keep the existing file until a replacement is downloaded and validated. If no candidate passes, show “No replacement found”; retain the current file and its blacklist entry. Retrying refresh does not exclude additional candidates unless a replacement succeeds.
5. **Delete:** remove only the managed theme file, remove its active-download record, and suppress automatic re-download for that item. A later explicit full rescan re-enables matching for it; the interface must state this behavior. Never delete other theme songs or the `theme-music/` directory.
6. **Rescan library:** a cancelable, progress-reporting task covering all selected movie/TV libraries. Skip items with an existing theme, including manual themes. Clear suppression for items explicitly deleted by this plugin so they can be searched again; leave existing managed themes alone. Show counts for added, already themed, no match, unsupported/unwritable, and failed items, with a rough ETA once enough items have completed.

## Functional requirements

### Matching and download

- Search with Jellyfin's display title and `OriginalTitle` when present, plus any already-known alternate/localized titles, production year where available, and theme/opening terms. Deduplicate equivalent titles and cap the total query/candidate count; aliases broaden retrieval, not acceptance. Review up to 30 lightweight search results, fetch full metadata for at most eight plausible candidates initially, and inspect the next eight only if no recording qualifies. If none qualifies, a matching full-album upload's first listed track can supply a bounded search hint, but never becomes a match without its own video metadata and the normal acceptance checks. Search snippets alone are not verified facts.
- **Reject before scoring:** a clear mismatch in work, edition, adaptation, movie-vs-series type, or release year; a sequel that is not the requested work, a video-game adaptation; a cover, remix, fan edit, extended suite, reaction, trailer, review, full album, compilation, or live stream. Keep identity qualifiers such as US/UK, original/remake, part number, and year during normalization rather than stripping them as noise. Match an alias only if the other evidence still identifies the *same edition*; a conflicting qualifier rejects the candidate. An unknown year is not a mismatch, but if it leaves two adaptations indistinguishable, record no match. The YouTube upload date is not a film/series release year.
- **Require a work-to-track link:** the candidate must identify the specific Jellyfin work in the video title, soundtrack album, or description. A named track like “Hedwig's Theme” can qualify if its description names the film, even without album, artist, or distributor metadata. The title should identify music, such as a theme, opening credits, soundtrack, score, or OST; an individual track with a matching soundtrack album and matching edition year can qualify without those title words when the track identity is available. For movies, prefer a main/title theme, then closing credits, then soundtrack tracks. The search query alone never establishes the work's identity. An uploader merely writing “official” is not evidence, and a trailer is not a theme.
- **Duration is both a hard gate and a ranking signal:** TV candidates must be 10 seconds to 5 minutes long; movie candidates must be 20 seconds to 8 minutes long. Reject unknown duration. Within those bounds, rank music near the typical theme length higher. Fetch full video metadata directly from each shortlisted URL before selection, and verify the downloaded audio's duration before committing it; flat search snippets alone are not sufficient.
- **Rank eligible recordings with weighted signals** for full or partial title overlap, theme and soundtrack terms, duration, channel name, and negative markers such as ranking videos. Structured album, track, artist and release-year metadata add evidence when present but are never required for directly titled themes. The raw score orders candidates, it is **not** a probability or a percentage. Popularity, views, and upload date do not add points.
- **Automatic acceptance:** all gates above pass; the score is positive; and one recording scores strictly higher than every competing recording. Group obvious duplicate uploads by reliable track/artist/edition evidence when comparing alternatives; equally ranked alternatives produce no match. Refresh also excludes the currently installed recording, not only its video ID. If search or metadata lookup partially fails, report a search failure rather than incorrectly declaring no match. A complete search that only finds a previously used recording counts as “Excluded”, not “No match found”. When a complete search finds no eligible candidate, record “No match found” with a persisted rejection reason (wrong version, uncertain track, conflicting alternatives, missing evidence, or overlong) and show recent skipped items on the scan page; do not prompt an admin to choose a candidate.
- **Observed search checks:** [The Office US search](https://www.youtube.com/results?search_query=the+office+us+opening+theme+song) also surfaces UK openings, short edits, and an official-channel “Best Intro Ever” clip; reject wrong versions and edits despite keyword/source bonuses. [Dune (2021) search](https://www.youtube.com/results?search_query=Dune+2021+main+theme+song) surfaces an official full album, Part Two tracks, and a TOTO main title for the older adaptation; none should automatically win. [Harry Potter search](https://www.youtube.com/results?search_query=Harry+Potter+and+the+Sorcerers+Stone+2001+main+theme) surfaces a [“Hedwig's Theme” recording](https://www.youtube.com/watch?v=wtHra9tFISY) whose title omits the movie, but whose album metadata identifies the film; do not reject it on title text alone. These are search/metadata checks, not audio verification or measured accuracy.
- **Processing budget:** matching uses search results and metadata for only a bounded shortlist; do not download or decode multiple candidates for scoring, run audio fingerprinting, speech/silence detection, or use a model to analyze audio. Download/convert the winning candidate, or one eligible alternate source if the first download fails after retries. When metadata cannot establish the correct recording, record no match and download nothing.
- Download audio only for the selected result and convert to a Jellyfin-readable format (`theme.mp3` initially). Limit candidate duration and output size, honor cancellation/rate limits, validate the resulting non-empty playable audio, and write to a temporary file in the target folder before an atomic rename. Failures must not leave a partial theme behind. The admin must supply/configure the necessary search credentials and download/conversion executables; missing prerequisites surface an actionable error.
- Normalize **every plugin-downloaded theme**, including Refresh replacements, during conversion using two-pass FFmpeg loudness normalization (EBU R128 `loudnorm`). Aim for **−18 LUFS integrated** and use a **−3 dBTP encoding target** to leave headroom for MP3 output. Do not reject playable audio solely because the encoded file deviates slightly from the target; conversion, size, codec, and duration validation remain required. Never process or change manually added theme songs. This is an audio-file target, separate from each Jellyfin client's playback volume control.
- Search and download operations have bounded retries/backoff for quota or transient failures. A failed source download can try one other eligible video from the same search, but must not persist a blacklist entry for a transient failure. A quota/auth/download failure is **not** “No match found” and must not overwrite an existing file.

### Filesystem ownership and safety

- Before any download or replacement, check both Jellyfin's recognized theme extras and physical theme files in the item's folder (`theme.*` and audio within `theme-music/`). Recheck immediately before committing the file. If any non-plugin-owned theme exists, skip the item, even if its name or extension differs from `theme.mp3`.
- Write `theme.mp3` next to the movie file in its **dedicated movie folder**, or in the **physical series root**. For a movie in a shared/flat folder, skip with an actionable “dedicated folder required” status instead of creating an ambiguous theme. Never derive a write path solely from a display title.
- Persist ownership as Jellyfin item ID + resolved canonical path + selected YouTube video ID + file hash + score and timestamp in plugin data (not alongside the media). On Refresh/Delete verify the file still exists at the recorded path, is inside the expected item folder, and still matches the recorded hash. If it was edited, moved, or replaced outside the plugin, treat it as user-owned and do not modify it. Reconcile the managed list when it is read, dropping records for definitively changed files or items no longer in Jellyfin while leaving files untouched; defer cleanup if the media folder is temporarily unavailable.
- Prevent overlapping work on the same item and avoid reprocessing theme extras emitted by library refresh events. Do not overwrite an existing destination, even if a stale plugin record claims ownership. After creating/removing a file, request a Jellyfin item metadata/filesystem refresh so the theme becomes visible/disappears without requiring a server restart.
- If a physical TV series is represented in multiple folders through automatic series grouping, manage each physical folder independently and display its library/path distinctly. Do not write into an inferred or grouped virtual location.

### Admin page and state

- Settings: enable/disable automatic processing, selected libraries, search credential, download tool status, and a link/button for full rescan. Do not expose credentials in logs or list responses.
- List: paginated/searchable plugin-managed downloads; show source link, item status, Refresh/Delete actions, and the added date. Page-wide failures use Jellyfin toasts; item-specific action failures appear in the affected row. Provide clear empty, in-progress, and missing/externally modified states. Unmatched items are counted in rescan results but do not create review tasks. Confirmation before Delete.
- Per-item blacklist contains rejected source **video IDs**, not titles; persist the rejected recording identity when it can be established reliably so Refresh cannot immediately choose another upload of the same audio. Refresh must select a *different* candidate meeting the acceptance rule; a rescan must respect blacklists. Records and blacklists survive restart. Deleted items' automatic suppression persists until an explicit full rescan re-enables them.
- Mutating actions and the management list require Jellyfin administrator authorization; return clear errors for missing items, unwritable media paths, stale ownership, and exhausted candidates.

## Acceptance criteria

1. Adding a movie in its own folder or a physical series in an enabled library queues one matching attempt; adding episodes, extras, virtual items, or items in disabled libraries does not.
2. A result passing identity, track, duration, score, and competing-recording checks becomes discoverable via Jellyfin's `Items/{itemId}/ThemeSongs` endpoint after refresh. A highly ranked but ambiguous result creates no file or admin review task; TV videos over 5 minutes, movie videos over 8 minutes, and videos with unknown duration are never downloaded, regardless of score.
   An alternate/localized title may retrieve a match, but a UK Office result for a US Office item or a 1984/Part Two Dune track for Dune (2021) must not be downloaded.
3. Manual `theme.*` files or audio in `theme-music/` block automatic downloads, refreshes, and rescan writes, with no modification to those files.
4. Refresh blacklists the current video ID and atomically replaces an unchanged plugin-owned file only when a *different recording* passes the acceptance rule; if none does, the old file remains and the UI explains why.
   A replacement whose conversion or output validation fails also leaves the old file untouched.
5. Delete removes only an unchanged plugin-owned file; externally edited files and stale records return a safe failure and are never deleted.
6. Full rescan processes all eligible selected-library items once, reports progress and outcomes, respects existing files and blacklists, and is cancelable; rerunning after a restart does not duplicate files.
7. Multiple concurrent additions/rescans/actions for the same item cannot overwrite each other or create duplicate downloads; a restart preserves ownership, blacklists, and explicit suppression.
8. Non-admins cannot list downloads, change configuration, trigger scans, or Refresh/Delete managed files.
9. New and refreshed plugin downloads are normalized toward −18 LUFS with MP3 encoding headroom and validated as playable audio; manual themes are neither measured nor modified by the plugin.

## Release dependencies and open decisions

- Pick the supported Jellyfin server release and validate plugin API/binary compatibility; the referenced `master` may differ from deployed releases.
- Decide which permitted YouTube search/download approach and redistribution model to support. Confirm applicable YouTube API terms, content rights, search quota/cost, and whether external `yt-dlp`/`ffmpeg` executables can be installed in target Jellyfin deployments before shipping download functionality.
- Calibrate score weights and acceptance thresholds on labeled movie/TV searches, including remakes, localized titles, named tracks, edits, and known false positives; prioritize the false-download rate over coverage.
